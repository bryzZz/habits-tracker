# Supabase — напрямую из фронтенда, без отдельного API-сервера

Когда прототип перейдёт с локального JSON-файла (см. [ADR-0003](0003-local-storage-is-a-real-json-file.md)) на Supabase, фронтенд будет обращаться к Supabase напрямую через client SDK и RLS-политики, без промежуточного собственного API-сервера. Конкретная цель хостинга: фронтенд на GitHub Pages, Supabase — единственный backend-as-a-service; отдельный собственный бэкенд сознательно не делается, чтобы не платить за его хостинг.

Это приложение — личный трекер для одного пользователя (схема данных включает `user_id` про запас). Для такого масштаба отдельный бэкенд не даёт ничего, кроме лишнего слоя для поддержки: вся нужная логика — CRUD по своим же данным — покрывается client SDK и RLS, а несложное администрирование (список привычек, каталог быстрых ответов) можно вести через админ-панель Supabase, а не строить свой UI. Экран логина в приложении всё же есть — см. [ADR-0008](0008-single-account-email-password-no-public-signup.md).
