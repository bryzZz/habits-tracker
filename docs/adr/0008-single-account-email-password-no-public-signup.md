# Единственный аккаунт, email/password, без email-зависимых флоу

Экран логина закрывает всё приложение — при отсутствии сессии любой маршрут редиректит на `/login`. Это пересматривает формулировку в [ADR-0004](0004-supabase-accessed-directly-from-frontend.md) («без экрана логина в прототипе»): авторизация здесь не про multi-tenant, а про доступ к данным одного и того же пользователя с нескольких устройств. Публичной регистрации в приложении нет — единственный аккаунт создаётся вне UI (см. [ADR-0009](0009-service-role-key-stays-in-local-account-script.md)).

Метод входа — email/password, а не magic link или OAuth. Оба варианта требуют инфраструктуры, которую решили не заводить сейчас: magic link и in-app сброс пароля упираются в дефолтный лимит Supabase на исходящую почту (2 письма/час, только на подтверждённые адреса) без custom SMTP; OAuth (Google и т.п.) требует отдельной регистрации OAuth-приложения. По той же причине сброс пароля в приложении не реализован — делается вручную через Supabase dashboard.

## Considered Options

- **Magic link** — отклонён: каждый вход требует письма, упирается в лимит 2 письма/час без custom SMTP.
- **OAuth (Google и т.п.)** — отклонён пока: нужна регистрация OAuth-приложения, сопоставимая по трудозатратам с настройкой SMTP; можно добавить позже.
- **Custom SMTP** — отклонён пока: снял бы оба ограничения выше, но это отдельная инфраструктура вне рамок этой сессии.
