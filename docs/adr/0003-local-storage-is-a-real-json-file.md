# Локальное хранение — JSON-файл на диске, не браузерное хранилище

Прототип (Vite + TypeScript + Tailwind) нужен до подключения Supabase. Обычный путь для чисто фронтенд-прототипа — localStorage/IndexedDB, без какого-либо сервера. Вместо этого решили хранить данные в настоящем JSON-файле на диске, читаемом и записываемом через небольшой локальный dev-сервер рядом с Vite.

Причины: пользователь явно попросил хранить данные «в файле» (а не «в браузере»), а сама история из `data.xlsx` (108 дней) переносится в приложение как есть — файл проще инспектировать, редактировать и в дальнейшем перегнать в Supabase как seed, чем вытаскивать данные из localStorage. Это осознанная промежуточная ступень: файл + локальный сервер существуют только до момента подключения Supabase, после чего эта прослойка убирается (см. [ADR-0004](0004-supabase-accessed-directly-from-frontend.md)).
