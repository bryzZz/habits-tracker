# Аккаунт создаётся локальным скриптом через Admin API; service_role key не покидает локальную машину

Единственный аккаунт (см. [ADR-0008](0008-single-account-email-password-no-public-signup.md)) создаётся одноразовым локальным скриптом — по аналогии с `scripts/extract_seed_data.py` — который вызывает `auth.admin.createUser` с `email_confirm: true` и паролем напрямую, без отправки письма. Скрипту нужен Supabase `service_role` key; он хранится только локально, не коммитится и никогда не используется в собранном фронтенде — это единственное место в проекте, где этот ключ вообще появляется. Согласуется с [ADR-0004](0004-supabase-accessed-directly-from-frontend.md): в браузер идёт только anon/publishable key, доступ к данным регулируется RLS.

Скрипт только создаёт аккаунт и не умеет сбрасывать пароль — при необходимости пароль меняется вручную через Supabase dashboard (Users panel), а не повторным запуском скрипта.
